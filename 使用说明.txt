【画迹1：落日情缘】存档工具 v1.2  ——  使用说明
============================================================

作者：@huxc573    开源地址：https://github.com/huxc573/huaji1-save-editor
开源协议：MIT License    问题反馈：https://github.com/huxc573/huaji1-save-editor/issues

【重要】本工具与游戏作者无关，游戏本体及其素材版权归原作者所有；
        请先自己备份 Audio\BGM\sy.ogg，改存档有风险。

一、这是什么
------------------------------------------------------------
本作（RPG Maker XP 做的《画迹1：落日情缘》）的存档是：

        Audio\BGM\sy.ogg

名字看起来像背景音乐，其实是加密后的存档文件。
本工具可以**解密查看并修改**这个存档。


二、怎么用
------------------------------------------------------------
1. 双击 画迹1存档工具v1.2.exe
2. 点左上角【选择存档…】，选中游戏目录里的 Audio\BGM\sy.ogg
   （程序启动时会自动找上次打开过的存档，所以通常打开就有内容）
3. 页签说明：
   概览 / 快捷修改   看存档概况；改金钱（元宝）、声望、仓库金额、步数
   全部解析数据      字段 / 类型 / 值 / 注释 四列（注释会告诉你这个字段是干什么的、
                     技能 id 对应哪个技能、物品实例用的哪个模板…）；
                     全局搜索（搜字段名或值），双击结果跳到树上；
                     对着标量字段右键 -> 「修改这个值…」就能改
   角色 / 召唤兽     左上角切换【人物】/【召唤兽】两组：
                     人物可改等级/经验/HP/SP/活力/体力/五维/潜力/附加属性；
                     召唤兽列表顺序与游戏界面一致（可勾选“显示无主”看已放生的），
                     可改等级/HP/SP/五维/潜力/成长/忠诚/六项资质，
                     下方还能【学会技能】/【忘掉选中】/【清空技能】
                     两组都能改名字（见下面“名字”一节）
   物品栏(道具/行囊/备用)  游戏里的三个 20 格容器（@pack / @wallet / @talisman）
                     顶部切换容器；格子/数量/物品id/品质 填好后点【写入 · 修改该格】；
                     【搜索物品】按名字或编号过滤物品列表（在物品 id 上方）；
                     【一键修复异常格】把游戏里用不了的格子按模板重建并登记
   开关 / 变量       双击即可切换/修改
   机器码            查看存档机器码与本机机器码；换电脑时改成新机器的
   说明 / 机制       存档格式与机制说明
   更新日志          各版本改了什么
4. 改完点【保存修改(Ctrl+S)】：
   · 原文件先备份成 sy.ogg.bak
   · 重新加密写回，然后重新解密读回校验

名字（人物 / 召唤兽都能改）：
   游戏显示名 = @new_name 存在 ? @new_name : @name
   （脚本 0040 Game_Battler#custom_name；玩家在游戏里花 30 活力改名，
    写的就是 @new_name）
   · 【设为显示名(@new_name)】：输入新名字后点它 —— 游戏里显示的就是它
   · 【改基础名(@name)】：改对象自己的名字字段
   · 【清除显示名(恢复原名)】：把 @new_name 删掉，恢复成游戏本名
   名字栏会实时显示：@name=… ｜ @new_name=… ｜ 游戏显示：…
   注：@new_name 平时不在存档里，改名会给对象加一个字段，
       工具会自动整条重写 $game_actors / $game_party，不会写坏链接。

‼ 召唤兽的 @name 千万不能改成 $pet 表外的名字：
   脚本 0011 里有一张按【宠物名字】索引的表（154 个名字）：
       $pet = { "宠物名" => [六项资质, [成长…], 参战等级], ... }
   而游戏这些地方【没有 nil 判断】地查它，名字对不上就报
       NoMethodError: undefined method '[]' for nil:NilClass
       （脚本 'Sys <召唤兽>' 的 147 行 $pet["#{baby.name}"][7]）
   召唤兽界面会直接打不开！
   本工具的对策：
     · 召唤兽表有「名字表」列（✔ 在表里 / ⚠ 不在表里）和「携带等级」列
     · 名字栏实时显示校验结果，给出应该改成的模板本名
     · 【改基础名(@name)】对召唤兽会先校验，不在表里就弹警告
     · 【恢复模板本名】：改回 $data_actors[模板].name
     · 【一键修复名字】：把名字异常的召唤兽批量改回去
     · 概览页也会直接提醒「⚠ 有 N 只名字不在 $pet 表里」
   ★ 想换好听的名字请用【设为显示名(@new_name)】—— 它不参与 $pet 查表，随便改。

召唤兽顺序 / 放生（看这里就不会迷惑）：
   · 游戏的召唤兽界面是按主人的 @babys 数组顺序显示的（脚本 0143
     Window_Baby#refresh），本工具的顺序与它完全一致，表格有「序」列
   · 放生（脚本 0044 remove_baby）只是把槽位从 @babys 里删掉、
     把 $data_actors[槽位] 清空，$game_actors 里的对象还留着 ——
     所以本工具默认**不显示**已放生的；勾上
     「显示无主（已放生）的召唤兽」才能看到这些残留数据（显示为灰色）

物品栏要点（写物品时最容易踩坑的地方）：
   · 容器：道具、行囊、备用 三个都是 20 格，顶部单选按钮切换
   · 格子：0 ~ 19，空的格子直接写入就是新增，已有物品的格子会被重建
   · 数量：至少是 1（填 0 会按 1 算；要清空请用【删除该格】）
   · 品质：至少是 1（填 0 或留空会按 100 算）—— 品质 0 的物品不能用
   · 登记：新物品的实例编号（@id）会自动分配，并把实例登记进 $data_items
     （游戏靠它判断“能不能使用”）；表格的“登记”列 ✔ = 游戏认得它
   · 改完物品想看效果：进游戏前先在工具里点一次【保存修改】；
     若之前用旧版本写坏过（物品不能使用、名字显示成 ?、图标不对），
     点【一键修复异常格】就能按模板重建并登记


三、依赖的文件（重要）
------------------------------------------------------------
程序目录里必须有下面三个文件（本包已附带，请勿删除）：

    XJCodec32.exe   自带的 32 位加解密宿主（只有 7.7 KB）
                    —— 游戏自带的 TP.dll / Socket.dll 是 32 位库，
                       64 位程序不能直接加载，所以用它中转
    TP.dll          游戏自带，负责加解密（DS1/DS2，口令 xjy.11）
    Socket.dll      游戏自带，负责取机器码（GetID）

**没有路径依赖**：把 exe 和这三个文件拷到任何地方都能用，
不需要游戏目录、不需要安装 Python，也不需要 PowerShell。

如果提示找不到 TP.dll：把游戏根目录（有 Game.exe 那层）里的
TP.dll 和 Socket.dll 复制到本程序旁边即可。


四、重要提醒
------------------------------------------------------------
* **改存档有风险**，请先自己复制一份 sy.ogg 留底！
  （工具也会自动生成 sy.ogg.bak，但多一份更保险。）
* 修改前请先**退出游戏**，否则文件被占用会保存失败。
* 保存后建议先进游戏确认，再继续大改。
* 金钱等数字在游戏里是 LockNumber 加密的（6 组校验），
  本工具会自动重算，不会触发游戏的"作弊惩罚"。
* 机器码不同会让游戏提示"存档的主人不是你"并退出 —— 换机器时
  在"机器码"页点【填入本机机器码】再保存即可。


五、本版（1.0）新增了什么（详见程序里的"更新日志"页）
------------------------------------------------------------
* 【严重修复】把召唤兽的 @name 改成表外的名字会让游戏直接报错
    现象：打开召唤兽界面弹
        脚本 'Sys <召唤兽>' 的 147 行发生了 NoMethodError.
        undefined method '[]' for nil:NilClass
    根因：0011 里 $pet 是以**宠物名字**为键的表
         （$pet = { "宠物名" => [六项资质,[成长…],参战等级] }，共 154 个名字），
         0163 第 147 行 $pet["#{baby.name}"][7] 没有 nil 判断；
         0044 里 @name = actor.name.split(/【/)[0]，而 Game_Actor#name 就是 @name。
         所以 @name 一旦不是 $pet 的键，$pet[名字] 就是 nil，nil[7] 直接抛异常。
    本版改动：召唤兽表加「名字表」「携带等级」两列；名字栏实时校验；
         【改基础名(@name)】对召唤兽会先拦一道并给建议；
         新增【恢复模板本名】/【一键修复名字】；概览页也会提醒。
* 【修复】改完名字后再改同一个对象的其它字段会报
         “该位置已被更大的改动覆盖，请先撤销那个改动”
    根因：整体重写一个对象（加/删 @new_name、改 @skills）之后，
         去改它内部字段时，新补丁落在那个更大的补丁里面。
    修法：新增 PatchEngine.replace_object() —— 整体重写时把这棵子树登记成
         “这一段的根”（和背包写入一样的机制），之后改内部字段会自动重算整块。
* 保留 0.7 的：召唤兽按界面顺序（主人 @babys）、已放生默认不显示、改名、
    解析页注释列（字段/类型/值/注释 四列）。


六、技术说明（给想继续研究的人）
------------------------------------------------------------
存档容器：

    [0D 0F 3E 03] [uint32LE 密文长度] [zlib 压缩的密文]

    TP.dll 的 DS1/DS2 自己负责整个容器，"给文件路径、原地改写文件"。

明文 = 19 个 Ruby Marshal 对象首尾相接：

    characters, frame_count, $game_system, $game_switches, $game_variables,
    $game_self_switches, $game_screen, $game_actors, $game_party, $game_troop,
    $game_map, $game_player, $data_items, $data_classes, $data_weapons,
    $data_armors, $data_actors, $data, $存档id

物品栏：游戏有三个 20 格容器 —— 道具 @pack、行囊 @wallet、备用 @talisman，
       每格 [RPG::Item 实例, 数量]。@standard 指向 data_items 的模板 id，
       @quality 是品质（两者模板里没有，是实例专有字段），
       @id 是实例编号 —— **它必须能在 $data_items 里查到**：
       游戏使用物品时执行 `item_can_use?($data_items[实例.@id])`
       （读 occasion），查不到（nil）就直接提示“该物品无法使用”。
       所以新物品要像游戏那样：@id = $data_items 的长度，并把实例 push 进去。

修改方式：解析时记录每个字段的字节区间，只把改动过的字段重新编码，
按原始偏移升序重放回明文，其余字节原样保留 —— 不会破坏对象链接（'@N'）
和 RPG::Table 之类的不透明数据。
整块替换（比如写一格物品）时会同时把新节点放回内存树，
所以界面能立刻看到新值，保存时再落回字节补丁。

对象链接（'@N'）—— 最容易写坏存档的地方：
  Ruby 存盘时，同一个对象第二次出现不再重写，只写一个 "@编号"。
  @pack 里第 2 格（佛手）的名字/图标/音效就是链接到第 1 格内部对象的。
  所以只改一格的字节、却改了这格内部的对象个数/顺序时，后面所有 "@编号"
  都会指错 —— 游戏读到名字是数组，就报 cannot convert Array into String。
  本工具的应对：只要动过物品栏，保存时整条 $data 流重新序列化，
  所有链接展开成独立副本（体积略增，但编号永远自洽）。

TP.dll / Socket.dll 是 32 位库，本工具用自带的 XJCodec32.exe（也是 32 位）
调用它们，全程静默、无窗口。

更详细的逆向结论见源码目录里的《结论-0.2.md》《结论-存档格式.md》。
