# 开发指南

面向"想改这个工具 / 想加新功能"的人。看完这篇你应该能：

* 在自己的机器上把项目和测试跑起来；
* 知道每个模块负责什么、改哪里；
* 知道有哪 **五条铁律**，违反了就会写坏别人的存档；
* 知道怎么打包、怎么定位游戏报错。

## 1. 目录与数据流

```
              ┌──────────────────┐
sy.ogg ──►    │ xj_codec.py      │  容器解析 / TP.dll(DS1,DS2) / 32 位宿主桥 / LockNumber
              └────────┬─────────┘
                       │ 明文(bytes)
              ┌────────▼─────────┐
              │ xj_marshal.py    │  Ruby Marshal 4.8 解析 ⇄ 序列化（对象编号规则与 Ruby 对齐）
              └────────┬─────────┘
                       │ 节点树（每个节点带"在明文里的字节区间"）
              ┌────────▼─────────┐
              │ xj_edit.py       │  写入引擎：区间补丁 / 整块重写 / 物品实例构造
              └────────┬─────────┘
                       │
              ┌────────▼─────────┐
              │ xj_model.py      │  游戏语义层 Doc：角色/召唤兽/物品栏/开关/字段注释表/保存
              └────────┬─────────┘
                       │
              ┌────────▼─────────┐
              │ xj_viewer.py     │  tkinter 界面（8 页签）
              └──────────────────┘
```

| 文件 | 职责 | 改它的时候注意 |
|---|---|---|
| `xj_codec.py` | 魔数/zlib/长度、`HostBridge` 调 `XJCodec32.exe`、`LockNumber` 解码、`app_dir()` | 宿主是 32 位的，别在 64 位进程里直接 `LoadLibrary` |
| `xj_marshal.py` | 解析器 `Parser`、各节点类、`serialize`、`reencode`、`parse_stream` | **对象编号规则**（见铁律 1）；新增类型一定要 `register()` |
| `xj_edit.py` | `PatchEngine`（`patch_range` / `replace_tree` / `replace_object` / `set_array_element`）、`clone_node`、`make_pack_entry`、`save_plain` | `replace_*` 三兄弟的区别见第 4 节 |
| `xj_model.py` | `Doc`：一切"游戏语义"（等级↔经验、资质、物品登记、名字表、`note_of`）、`CHANGELOG` | 写入前想一下"对象个数会不会变" |
| `xj_viewer.py` | 界面 + 自检（`XJ_SELFTEST=1` 跑 `--selftest`） | 界面操作后要 `fill_*()` 刷新 + `mark_dirty()` |
| `xj_env.py` | **开发期**辅助：`game_dir()` 定位游戏目录 | 应用本体不依赖它 |

## 4. ★ 五条铁律（违反就会写坏存档）

### 铁律 1：Ruby Marshal 的对象编号

```
除 nil / true / false / Fixnum / Symbol 外，一切对象都占一个编号，编号 = 出现顺序。
'@N' 只能引用前面出现过的对象。
```

所以只要**改变了某个对象内部的对象个数**（加/删 ivar、改数组长度、
把 `@N` 链接换成内联值……），它后面所有 `@N` 的编号都会整体偏移。

三种处理方式，选错就出事：

| 方法 | 用途 | 是否登记为"根" |
|---|---|---|
| `pe.set_scalar(node, v)` | 改一个**标量**（长度不变） | — |
| `pe.set_array_element(arr, i, node)` | 替换数组的一个元素（例如物品格） | ✅ 整格 |
| `pe.replace_object(node, span=None)` | 整体重写**一个对象**（加/删 ivar、数组长度变） | ✅ 该对象 |
| `pe.replace_tree(node)` | 整条重写（顶层对象）—— 只用在 `Doc.save()` 里 | — |

"登记为根"（`_tag_new` + `_roots[span] = node`）的含义：
之后改这棵子树内部的字段时，`set_scalar` 会自动**重新序列化整块**，
而不是打一个"落在更大补丁里面"的小补丁（那会直接抛
`EditError: 该位置已被更大的改动覆盖`）。

写完还要标记"需要整条重写顶层对象"：

```python
self._actors_dirty = True   # 保存时整条重写 $game_actors / $game_party
self._pack_dirty   = True   # 保存时整条重写 $data
self._tpl_dirty    = True   # 保存时整条重写 $data_items
```

`_check_links()` 会在重写前做全树体检，`LinkNode.target is None` 就拒绝写入。

### 铁律 2：物品实例必须登记进 `$data_items`

见 [`机制笔记-物品栏.md`](机制笔记-物品栏.md)。要点：
实例的 `@id` 必须是 `$data_items` 的有效下标，且要写出 `@quality`。
工具里的入口是 `Doc.pack_write()` → `Doc.register_item()` / `next_item_db_id()`。

### 铁律 3：召唤兽的 `@name` 必须在 `$pet` 名字表里

见 [`机制笔记-角色与召唤兽.md`](机制笔记-角色与召唤兽.md)。要点：
游戏 5 处无 nil 判断地执行 `$pet["#{名字}"][7]`，改错就是
`NoMethodError: undefined method '[]' for nil:NilClass`。
想换显示名请写 `@new_name`。

### 铁律 4：整数编码 —— 4 字节是硬上限，负数要带符号字节

Ruby 1.8 的整数编码坑最多，**两个都真实写坏过存档**：

```text
0                       -> 00
0 < x < 123             -> x + 5          （一个字节的"直接值"）
-124 < x < 0            -> (x-5) & 0xFF
其它正数                 -> 长度字节(1..4) + 小端字节
其它负数                 -> 长度字节 = 256-n + 补码最小长度的**小端**字节
```

* **长度字节只能是 1..4**：`5..0x7F` 之后的字节会被读成"直接值 0..122"。
  ⚠ 需要 5 个字节的整数（例如 LockNumber 的上亿中间值）**必须写成大整数 `'l'`**，
  否则长度字节写成 `05` 后**一个字节都不多消耗**，整条流从此错位
  （表现为 `MarshalError: 未知类型 't' (0x74)`）。用 `M.encode_integer()`。
* **负数要用补码最小长度**：`-65535` 写成 `fe 01 00` 会被解成 `+1`，
  必须写成 `fd 01 00 ff`。
* **边界（本作实测）**：`@cash` 里有 `69 04 9c cb 2f 8d` = 2368719772
  （第 31 位是 1）这种 4 字节 Fixnum ⇒ 正数上限是 `0xFFFFFFFF`，
  不能按"有符号 32 位"把它升级成大整数，否则"改回原值"也会算成改动。
* 这些规则由 `tests/test_marshal_fix.py` 逐个边界值守着，改编码一定要先跑它。

### 铁律 5：整条重写要能处理循环引用

战斗过的存档里 `Game_Actor#@who_attack_me`（`Game_Enemy`）的 `@who_attack_me`
会用 `'@N'` 指回同一个 `Game_Actor` —— 这是**真循环**，Ruby 就是靠 `'@N'` 表达它的。

* `M.serialize(node)`（展开模式）遇到环会无限递归 → 报"序列化嵌套过深"；
* `M.serialize(node, table={})`（编号模式）按 Ruby 规则发 `'@N'` 引用，环自然收住，
  **整条重写顶层对象 / 原地重写子树都应该用它**（`xj_edit._dump()` 已封装）：
  * 整条重写顶层对象：编号从 0 开始，完全自洽；
  * 原地重写子树：编号从该节点的 `gidx` 开始，**区间内部重新编号但对象个数不变**，
    所以后面兄弟节点里的 `'@N'` 不会被弄错位（这也是别用展开模式改子树的原因）。

### 铁律 6：数组元素**可能就是 `'@N'` 链接**，别当成"不存在"

`$game_actors.@data[槽位]` 不一定是对象，也可能是 `'@N'` 引用：

```ruby
$game_actors.@data[165]  ==  '@62'          # 数组里只是个引用
         真正的对象在  $game_actors.@data[12].@who_attack_me.@who_attack_me
         （宠物被挂进了人物的战斗状态对象里）
```

* Ruby 里 `$game_actors[165]` 照常能取到对象，**游戏显示完全正常**；
* 但工具若只认 `ObjNode`，那只召唤兽就在列表里"消失"了
  （v1.2 修的就是这个 —— 用户看到"游戏里有 3 只，工具只列 2 只"）。
* 所以：**凡是按数组下标找对象的地方，都要解引用**。
  `Doc.actors()` 已统一处理（`LinkNode` → `target`），
  回归测试是 `tests/test_pets.py` 里"@babys 里的槽位都能列出来"那一项。

## 5. 怎么加一个新功能

以"加一个『一键满资质』按钮"为例：

1. **先在游戏脚本里找依据**（`probes/probe_show_script.py`）：
   这个字段是干什么的？有没有别的联动字段？（例如改等级要同步 `@exp`）
2. **模型层加方法**（`xj_model.py` 的 `Doc`）：
   ```python
   def max_pet_zz(self, aid):                 # 返回改了哪些，方便 UI 显示
       pe = self.begin_edit()
       ...
       self._actors_dirty = True              # 想清楚要不要重写顶层
       return changed
   ```
   一律用 `self.begin_edit()` 拿 `PatchEngine`，不要自己造。
3. **界面层加按钮 + 回调**（`xj_viewer.py`）：回调里 `mark_dirty()` →
   `fill_actors()` → `select_actor()` → `load_actor_edit()`，让界面立刻反映新值。
4. **加测试**（`tests/test_xxx.py`）：至少覆盖
   "改完内存里对得上 / 保存读回还对 / 其它对象字节没变"。
5. **更新 `CHANGELOG`**（`xj_model.py` 里的 `CHANGELOG` 字符串，界面会显示）
   和 `CHANGELOG.md`。

## 6. 打包

```powershell
$env:XJ_GAME = "D:\Games\画迹1：落日情缘"
python tools\build.py              # 编译宿主 + 准备 dist/ + PyInstaller 打包
python tools\build.py --nopack     # 只准备 dist/（调试用）
python tools\build.py --hostonly   # 只编译 32 位宿主
```

流程与踩坑：

1. **编译 32 位宿主**：`csc.exe /platform:x86 /target:exe`（.NET Framework 4.x 自带），
   产物 `src/XJCodec32.exe`（约 7 KB）。
2. **准备 `dist/`**：`XJCodec32.exe` + `使用说明.txt` +
   **从游戏目录复制** `TP.dll` / `Socket.dll`（仓库里不放这两个游戏文件）。
3. **PyInstaller**：

   ```powershell
   pyinstaller --onefile --windowed --name 画迹1存档工具v1.0 ^
       --distpath dist --workpath build --specpath . --paths src ^
       --add-data "<python>\tcl\tcl8.6;tcl/tcl8.6" ^
       --add-data "<python>\tcl\tk8.6;tcl/tk8.6" ^
       src\xj_viewer.py
   ```

   * **tcl 库不会被自动收集**，必须 `--add-data` 带上，并在 `import tkinter` 之前
     设置 `TCL_LIBRARY` / `TK_LIBRARY`（见 `xj_viewer._setup_tcl_env()`）；
   * `--windowed` 的 exe 没有控制台，未捕获异常会写 `error.log`，
     带 `XJ_SELFTEST=1` 或 `--selftest` 会写 `selftest_result.txt`；
   * 打包后 `src/pet_table.py` 会被静态分析收进去 —— `tests/test_bundle_pet_table.py`
     专门验证这一点。

4. **从测试脚本启动 exe 前**要清掉 `PYTHONHOME` / `PYTHONPATH` / `VIRTUAL_ENV`，
   否则 exe 会以退出码 1 失败（uv 版 Python 的环境变量会干扰 PyInstaller 的引导）。

### 6.1 发布到 GitHub Release —— 附件名必须是 ASCII

**坑（踩过）**：`gh release create ... 'dist\画迹1存档工具v1.0.exe'` 上传成功后，
资源名变成了 `1.v1.0.exe`；`使用说明.txt` 变成了 **`default.txt`**，
还顺手把别人同名附件覆盖了。

* GitHub 会**剔除 Release 资源名里的非 ASCII 字符**；名字被剔空就退回 `default`。
* `gh` 的 `路径#名字` 语法里，`#` 后面的是页面上的 **Label**，
  真正的资源名仍取**本地文件名**（所以不能靠 `#` 改名）。
* `gh` 传中文**参数**给 GitHub 没问题（Python `subprocess` 走 UTF-16 命令行；
  PowerShell 直接传中文给 `gh.exe` 会受控制台代码页影响）。

正确做法：**先把文件复制成 ASCII 名再上传**，中文放在 `#label` 里：

```powershell
# 用 Python 调 gh（subprocess 走 UTF-16，中文参数不会丢）
gh release upload v1.0 --clobber 'dist\release\huaji1-save-editor-v1.0.exe#画迹1存档工具v1.0.exe'
gh release upload v1.0 --clobber 'dist\release\USAGE.txt#使用说明.txt'
```

结果：下载 URL 是 ASCII（`.../download/v1.0/huaji1-save-editor-v1.0.exe`），
Release 页面上显示的是中文 Label。改完记得同步 README 的下载表。

## 7. 调试技巧

| 需求 | 做法 |
|---|---|
| 看某个字段的字节区间 | 界面「全部解析数据」选中该行，详情区会显示 `明文偏移：a..b（n 字节）` |
| 导出一整棵解析树 | 界面【导出报告】/【导出明文】 |

| 定位游戏报错的行 | [`排错指南.md`](排错指南.md) |
| 想加日志 | 构造 `Doc(..., log=print)`，`begin_edit`/`save` 的关键步骤都会打出来 |

## 8. 代码风格约定

* Python 3，`# -*- coding: utf-8 -*-`，注释和文档用中文（目标读者是中文玩家）；
* 尽量不引入第三方依赖：**运行时只用标准库**（`tkinter` / `zlib` / `subprocess`…），
  只有构建时需要 `PyInstaller`；
* 面向"以后还要改"写：遇到的坑都写在注释里（为什么这样写，而不是写什么）；
* 模型层不要 `import tkinter`；界面层不要直接操作字节。
