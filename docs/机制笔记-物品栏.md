# 机制笔记：物品栏

对应存档位置：`$data`（`System::Data`）里的三个数组。
相关脚本：`0155 Sys::Data 1`、`0156 Sys::Data 2`、`0162`（使用物品）、`0140`（物品窗口）。

---

## 1. 三个 20 格容器

`$game_party.@items` **不是**背包 —— 真正的背包在 `System::Data` 里：

| 中文名 | 存档字段 | 类 |
|---|---|---|
| 道具 | `$data.@pack` | `Array[20]` |
| 行囊 | `$data.@wallet` | `Array[20]` |
| 备用 | `$data.@talisman` | `Array[20]` |

每格的结构：

```ruby
[ RPG::Item 实例, 数量 ]       # 数字表示数量
nil                            # 空格子
```

## 2. 物品实例的字段

模板在 `Data/Items.rxdata`（`RPG::Item`，**25 个字段**）：

```
@id @name @icon_name @description @scope @occasion @animation1_id
@animation2_id @common_event_id @price @consumable @parameter_type
@parameter_points @recover_hp_rate @recover_hp @recover_sp_rate
@recover_sp @hit @pdef_f @mdef_f @variance @element_set
@plus_state_set @minus_state_set @menu_se
```

> `@menu_se` 是 `RPG::AudioFile(@name, @volume, @pitch)`。

**实例是 27 个字段 = 模板 25 + 以下 3 个（其中一个覆盖 `@id`）：**

| 字段 | 含义 | 坑 |
|---|---|---|
| `@standard` | 模板 id（对应 `$data_items` 的下标），名字/图标/效果都看它 | 模板里没有，必须自己写 |
| `@id` | 该实例的唯一编号 | **必须能在 `$data_items` 里查到**（见下） |
| `@quality` | 品质 | **模板里没有**；缺了游戏读到 `nil` 当 0 处理 → 物品点不动 |

实测：模板 25 个字段、实例 27 个字段（`probes/probe_item_fields.py` 就是干这个的）。

## 3. ★ 为什么新物品"无法使用"

### 3.1 判定链

```ruby
# 0162：使用物品时，传进去的是【实例的 @id】，不是 @standard
if !$data.item_can_use?(item[0].id)
  # → "该物品无法使用！再试也不能用，233333"
end
```

```ruby
# 0155 System::Data#item_can_use?(item_id)
return if $data_items[item_id].nil?      # ← 查不到就直接 return（判为不能用）
occasion = $data_items[item_id].occasion # 0/2=平时可用，1=仅战斗，3=不能用
```

⇒ **实例的 `@id` 必须是 `$data_items` 里有效的下标，而且那一项的 `@standard` 要和实例一致。**

### 3.2 游戏自己是怎么新增物品的

```ruby
# 0156 random_item(item_id)
item = $data_items[item_id].clone
item.standard = item_id
item.id       = $data_items.size     # 新槽号
$data_items.push(item)               # 登记！
```

本工具完全照做：`Doc.register_item()` + `Doc.next_item_db_id()`，
保存时整条重写 `$data_items`（它内部有 112 个 `@N` 链接，必须整条重写才安全）。

`Doc.registration_state(iid, standard)` 用来检查一个实例是否合法，返回
`ok` / `missing` / `out_of_range` / `std_mismatch`，界面上的「登记」列就是它。

### 3.3 "一键修复异常格"

`Doc.pack_scan_bad()` 扫出这些情况并按模板重建 + 登记：

* 缺 `@quality`；
* 数量异常（< 1 或不是整数）；
* 缺 `@standard`；
* `@name` / `@icon_name` / `@description` 解出来不是字符串
  （说明是**对象链接错位**，档被旧版本写坏过）。

## 4. 为什么"从行囊搬回背包会填满背包"

这是**游戏自己的设定**，不是 bug：

```ruby
# gain_item：模板的 element_set 里含 26 时，每个只放一格
```

模板 87（祈福酒肆）的 `element_set = [26]`，表示**不可叠加**，
所以 `n.abs.times` 会给每一件创建一个独立格子 —— 搬到只有 20 格的背包里
自然就"填满"了。

判断办法：看模板的 `@element_set` 里有没有 26。

## 5. 物品模板 / 名称从哪来

| 数据 | 来源 |
|---|---|
| 模板（名字/图标/效果/价格） | 存档里的 `$data_items`（`Data/Items.rxdata` 的运行时快照） |
| 有没有名字 | 本作 `$data_items` 里有 **433** 个有名字的物品（含运行时新增的） |

`Doc._db('data_items', 'Items.rxdata')` 优先用存档里的那一份；
如果存档里没有这个顶层对象（理论上不会），才去找 `<游戏目录>/Data/Items.rxdata`。

搜索框支持按**名字**或**编号**过滤，例如输入 `祈福` 或 `87`。

## 6. 界面速查

| 控件 | 作用 |
|---|---|
| 顶部单选 | 切换 `道具 @pack` / `行囊 @wallet` / `备用 @talisman` |
| 表格列 | 格 / 物品名（实例） / 模板id / 实例id / 数量 / 品质 / **登记** / 说明 |
| 格子 + 数量 + 品质 + 物品id | 填好后点【写入 · 修改该格】。空格子 = 新增；已有物品的格子 = **覆盖重建**（沿用原实例 id） |
| 【删除该格】 | 把那格改成 `nil` |
| 【搜索物品】 | 关键字或编号过滤下拉列表 |
| 【一键修复异常格】 | 扫描 + 按模板重建 + 登记 |
