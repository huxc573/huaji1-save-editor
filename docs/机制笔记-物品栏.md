# 机制笔记：物品栏

对应存档位置：`$data`（`System::Data`）里的三个数组。
相关脚本：`0155 Sys::Data 1`、`0156 Sys::Data 2`（新增物品）、`0162`（使用物品）、`0140`（物品窗口）。

---

## 1. 三个 20 格容器

`$game_party.@items` **不是**背包 —— 真正的背包在 `System::Data` 里：

| 中文名 | 存档字段 | 类 |
|---|---|---|
| 道具 | `$data.@pack` | `Array[20]` |
| 行囊 | `$data.@wallet` | `Array[20]` |
| 备用 | `$data.@talisman` | `Array[20]` |

每格的结构：

```ruby
[ 实例, 数量 ]       # 数字表示数量
nil                  # 空格子
```

---

## 2. ★★ 一格里的实例有三种类（最容易翻车的地方）

**不是**所有实例都是 `RPG::Item`。看 Ruby 类名分三种，**模板表 / 登记表各不相同**，
三者的 `@id` 是**三套互相独立的编号空间**：

| 实例类 | 模板表 = 登记表 | 典型东西 | 模板字段 | 实例字段 |
|---|---|---|---|---|
| `RPG::Item` | `$data_items`（`Data/Items.rxdata`） | 药品、食物、任务道具 | 25 | 27（+`@standard` +`@quality`） |
| `RPG::Weapon` | `$data_weapons`（`Data/Weapons.rxdata`） | **武器**、召唤兽的**灵石 / 糖果 / 兜兜** | 18 | 20（+`@standard` +`@identify` +`@f_element`） |
| `RPG::Armor` | `$data_armors`（`Data/Armors.rxdata`） | 人物**防具** | 16 | 19（+`@standard` +`@identify` +`@f_element`） |

### 2.1 ★ 宠物武器（泡泡兜兜 / 灵石 / 糖果）按行为是"物品"（1.5.1）

游戏脚本 0162：`RPG::Weapon` 且 `element_set` 含 **98**（宠物武器）时，右键
「使用」→ 要求有参战召唤兽 → `baby.equip(2, 实例.id)` → **背包格置 nil
（用一次消失）**。所以这批东西按行为是**物品**，不是装备：

* 界面一律按「物品」展示（类列 / 搜索后缀 / 下拉归类到物品类）；
* 但实例的 Ruby 类仍是 `RPG::Weapon`、**登记必须在 `$data_weapons`** ——
  `baby.equip` 内部走 `$data_weapons[实例.id]` 解析（脚本 0044）；
* `pack_write()` 收到物品类的宠物武器 id 时自动路由回装备表（仅当
  `$data_items` 同一编号**没有带名字的真模板**时——items[468] 是无名占位）；
* 装备类下拉不再列出它们（全部 29 件灵石 + 4 件糖果/兜兜 + 实例克隆）。

依据是游戏脚本 0156：

```ruby
def gain_item(item_id, n)     # -> $data_items
def gain_weapon(weapon_id, n) # -> $data_weapons
def gain_armor(armor_id, n)   # -> $data_armors
```

`random_item` 登记进 `$data_items`、`random_weapon` 登记进 `$data_weapons`、
`random_armor` 登记进 `$data_armors`；后两者还会把新实例的 id
**并进对应职业的 `@weapon_set` / `@armor_set`**（不然职业穿不上）。

> ⚠ **1.4.0 及以前：整条物品栏只认 `$data_items`。** 后果有三个：
> ① 装备 / 防具的模板**一个都选不到**（泡泡兜兜 = `$data_weapons[468]`、
> 灵石 23 件从 443 起、大海龟 / 海毛虫糖果 466/467 —— 一共 **529 个**模板）；
> ② 这些格的「登记」列**全判 ✘**；
> ③ 致命：点【一键修复异常格】会按 `$data_items` 把它们**重建**成同编号的物品
> ⇒ 银腰带、珍珠链会被换成「狼●孵化蛋」之类。**真档三容器 23 个在用格里，
> 15 格是装备 / 防具 —— 旧版点一下就会毁掉 15 格。**

> 实测（本机真档）：有名字的模板 物品 **424** / 装备 **390** / 防具 **139**；
> 下拉从 424 项变 953 项。

## 3. 实例字段

### 3.1 物品 `RPG::Item`

模板 25 个字段：

```
@id @name @icon_name @description @scope @occasion @animation1_id
@animation2_id @common_event_id @price @consumable @parameter_type
@parameter_points @recover_hp_rate @recover_hp @recover_sp_rate
@recover_sp @hit @pdef_f @mdef_f @variance @element_set
@plus_state_set @minus_state_set @menu_se
```

> `@menu_se` 是 `RPG::AudioFile(@name, @volume, @pitch)`。

**实例 27 = 模板 25 + 以下字段（其中 `@id` 覆盖模板同名）：**

| 字段 | 含义 | 坑 |
|---|---|---|
| `@standard` | 模板 id（对应 `$data_items` 的下标），名字/图标/效果都看它 | 模板里没有，必须自己写 |
| `@id` | 该实例的唯一编号 | **必须能在 `$data_items` 里查到**（见下） |
| `@quality` | 品质 | **模板里没有**；缺了游戏读到 `nil` 当 0 处理 → 物品点不动 |

### 3.2 装备 / 防具 `RPG::Weapon` / `RPG::Armor`

模板 18 / 16 个字段；实例比模板多 `@standard`（模板 id）、`@identify`（鉴定，随机 `true/false`）、
`@f_element`（属性）。**没有 `@quality`** —— 所以装备 / 防具的「品质」列一律显示 `-`。

## 4. ★ 为什么新物品“无法使用”

### 4.1 判定链

```ruby
# 0162：使用物品时，传进去的是【实例的 @id】，不是 @standard
if !$data.item_can_use?(item[0].id)
  # → “该物品无法使用！再试也不能用，233333”
end
```

```ruby
# 0155 System::Data#item_can_use?(item_id)
return if $data_items[item_id].nil?      # ← 查不到就直接 return（判为不能用）
occasion = $data_items[item_id].occasion # 0/2=平时可用，1=仅战斗，3=不能用
```

⇒ **实例的 `@id` 必须是它那一类登记表里的有效下标。**

### 4.2 游戏自己是怎么新增物品的

```ruby
# 0156 random_item(item_id)
item = $data_items[item_id].clone
item.standard = item_id
item.id       = $data_items.size     # 新槽号
$data_items.push(item)               # 登记！

# random_weapon / random_armor 同理，只换成 $data_weapons / $data_armors，
# 再加一句：把新 id 并进对应职业的 @weapon_set / @armor_set
```

本工具完全照做：`Doc.register_instance(kind, iid, node)` + `Doc.next_db_id(kind)`，
保存时整条重写**被改过的那张表**（表内部有大量 `@N` 链接，必须整条重写才安全）；
写装备 / 防具会顺手 `Doc.bind_to_classes()`。

`Doc.registration_state(iid, standard, kind)` 用来检查一个实例是否合法，返回
`ok` / `missing` / `out_of_range` / `std_mismatch`，界面上的「登记」列就是它。

### 4.3 “一键修复异常格”

`Doc.pack_scan_bad()` **按类别**扫出这些情况并按模板重建 + 登记：

* 物品：缺 `@quality`；装备 / 防具：缺 `@identify`；
* 数量异常（< 1 或不是整数）；
* 缺 `@standard`；
* `@name` / `@icon_name` / `@description` 解出来不是字符串
  （说明是**对象链接错位**，档被旧版本写坏过）；
* 没登记在**对应类别**的登记表里。

`Doc.pack_fix_all()` 修复时会带上该项的 `kind`，**按它自己那一类的模板重建**。

## 5. 为什么“从行囊搬回背包会填满背包”

这是**游戏自己的设定**，不是 bug：

```ruby
# gain_item：模板的 element_set 里含 26 时，每个只放一格
```

模板 87（祈福酒肆）的 `element_set = [26]`，表示**不可叠加**，
所以 `n.abs.times` 会给每一件创建一个独立格子 —— 搬到只有 20 格的背包里
自然就“填满”了。

判断办法：看模板的 `@element_set` 里有没有 26。

## 6. 物品模板 / 名称从哪来

| 数据 | 来源 |
|---|---|
| 模板（名字/图标/效果/价格） | 存档里的 `$data_items` / `$data_weapons` / `$data_armors`（`Data/*.rxdata` 的运行时快照） |
| 有名字的模板数（本机真档） | 物品 **424** / 装备 **390** / 防具 **139** |

> ⚠ 登记表**会随游戏运行变长**（新增实例会 push 进去），所以“数组长度”不是模板数 ——
> 本工具取 `max(登记表长度, 内嵌名字表长度)` 当遍历范围，只把**有名字**的当模板列出来。

`Doc.db_array(kind)` 优先用存档里的那一份；如果存档里没有这个顶层对象（理论上不会），
才去找 `<游戏目录>/Data/*.rxdata`。

搜索框支持按**名字**或**编号**过滤，例如输入 `祈福` 或 `87`。

## 7. 界面速查

| 控件 | 作用 |
|---|---|
| 顶部行 1 单选 | 切换 `道具 @pack` / `行囊 @wallet` / `备用 @talisman` |
| 顶部行 2 单选 | **类别**（按实例的 Ruby 类）：物品 / 装备 / 防具 —— 决定查哪张模板表与登记表。⚠ 与上面的**容器**是两回事：装备 / 防具平时也装在 `@pack` 里，所以会出现在「道具」页 |
| 表格列 | 格 / **类** / 物品名（实例） / 模板id / 实例id / 数量 / 品质 / **登记** / 说明 |
| 格子 + 数量 + 品质 + 物品id | 填好后点【写入 · 修改该格】。空格子 = 新增；已有物品的格子 = **覆盖重建**（同模板沿用原实例 id） |
| 【删除该格】 | 把那格改成 `nil` |
| 【搜索物品】 | **跨三类**搜（名字或编号）；命中行标出所属类别，选中后**自动把类别切过去** |
| 【一键修复异常格】 | 按**各自类别**扫描 + 重建 + 登记（不会再把装备当物品换掉） |
| 滚动条 | 纵横各一条（20 格 + 长「说明」都看得到） |
| 列宽 | 按窗口宽度自适应，余量给「说明」列 |
| 悬停说明 | 鼠标停在表格某行 / **下拉某项**上，弹出 `@description`（与游戏 tooltip 同源，见 §8） |

> 冲掉（1.5.0 里先选「泡泡兜兜」再点空格，类别会被顶回"物品"→ 写成 ？/别的

## 8. 悬停说明是怎么做的（含一个 Tk 的坑）

鼠标停在**表格某一行**或**下拉里的某一项**上，都会弹出那一条的完整说明：

```
名字 ｜ 类别 id N

<模板 @description>
```

内容来自 `SaveDoc.template_tip(kind, i)` —— 和游戏里那个 tooltip 同源。

### 表格行

`Treeview.bind('<Motion>')` → `identify_row(y)` → 从行里取「说明」列；
说明太短就退回按「模板id」列去查 `template_tip`。`<Leave>` 收提示。

### 下拉项（⚠ 这里踩过一个坑）

ttk 的 `ttk.Combobox` 下拉列表**不是** Python 侧建的控件，而是 Tcl 自己建的原生窗口：

```
<combobox>.popdown          # ComboboxPopdown（toplevel）
  └── .f                    # ttk::frame（ttk::combobox::PopdownWindow 的返回值）
        ├── .f.l            # listbox ← 要绑的就是它
        └── .f.sb           # 滚动条
```

两个坑：

1. **别用 `widget.nametowidget('<combobox>.popdown.f.l')`。** tkinter 的
   `nametowidget` 是拿 `parent.children[...]` 一层层走的，而 popdown 是 Tcl 直接
   `toplevel` 出来的，**从没登记进任何 Python 控件的 `children`** ⇒ 直接
   `KeyError: 'popdown'`（旧版就是栽在这里：绑定静默失败、悬停没反应）。
   改成**用 Tcl 路径定位 + 在 Tcl 层 bind**：
   `ttk::combobox::PopdownWindow <cb>` 拿 `.f`，再在 `winfo children` 里按
   `winfo class == Listbox` 挑出 `.f.l`；绑定一律走 `root.tk.call('bind', ...)`
   （Python 回调先用 `root.register()` 注册成 Tcl 命令，**只注册一次**）。

2. **时机：只能挂 `-postcommand`。** `ttk::combobox::Post` 的顺序是
   「先跑 `-postcommand` → 再 `PopdownWindow` → 再 `ConfigureListbox`（这时才把值
   填进 listbox）→ 最后 `wm deiconify`」。而且下拉收起后 **popdown 只是 `wm withdraw`，
   控件本身一直活着**，所以每次弹出前重新绑一遍即可（不加 `+`，重复绑只覆盖不堆叠，
   也不会碰到 ttk 自己的 `ComboboxListbox` / `Listbox` bindtag 上的点选、Esc 绑定）。

3. 弹出时 ttk 会给 popdown 设**全局 grab**（`ttk::globalGrab`），但事件照样会派发到
   grab 窗口的后代（listbox）上，所以 `<Motion>` 收得到 —— 这一点用「屏幕外映射 +
   真 `<Enter>`/`<Motion>` 事件」验过（见 `tests/test_gui.py` 里那段断言）。

### 提示窗

一个 `overrideredirect` 的 `Toplevel`：`-topmost`（不然会被 topmost 的下拉盖住）、
贴到屏幕边会自动翻到指针另一侧、内容不变时不重画（`_tip_row` / `_tip_item` 去重）。
