# 存档格式（逆向结论）

本文记录《画迹1：落日情缘》（RPG Maker XP / RGSS 1.8）存档的**实测格式**。
所有结论都来自对 `Audio/BGM/sy.ogg` 与游戏脚本明文的交叉验证，文中给出的
"脚本 00xx"是脚本段编号（游戏是加密的 `Data/Scripts`，编号方式见
[`逆向过程与工具.md`](逆向过程与工具.md)）。

---

## 1. 文件在哪

| 项 | 值 |
|---|---|
| 路径 | `<游戏目录>\Audio\BGM\sy.ogg` |
| 依据 | 脚本 `0030 Module Save_Load` 里 `$save_path = "Audio/BGM/sy.ogg"` |
| 说明 | 名字伪装成 BGM，实际不是音频；同目录下其他 `*.ogg/mp3` 是真音乐 |

> 另外 `Scene_Title` 里有一段：如果存在 `Save1.rxdata` 就把它复制成 `sy.ogg`
> （官方"换存档"入口）。用别人的存档时要留意这一点。

## 2. 容器格式

```
偏移 0   0D 0F 3E 03              魔数（uint32LE = 0x033E0F0D）
偏移 4   <uint32 LE>              密文长度
偏移 8   78 9C ...                zlib 压缩的密文
```

* 实测：文件大小 `2,002,229` 字节，声明密文长度、zlib 解出长度、解出明文长度
  三者可互相校验。
* **注意**：`TP.dll` 的 `DS1` / `DS2` **自己负责整个容器**（魔数 + 长度 + zlib 都在它内部
  处理），不要把 zlib 剥好再喂给它。它们接收的是**文件路径**，并且**原地改写文件**，
  与文件名无关。

## 3. 加解密

```
TP.dll  导出 DS1(明文文件, 口令)  → 加密（原地写回）
        导出 DS2(密文文件, 口令)  → 解密（原地写回）
口令 = "xjy.11"
```

* 已实测 `DS1(DS2(file))` 与原文件逐字节相同（MD5 一致）。
* **算法是自定义的**：8 字节块、密文长度 `ceil((n+2)/8)*8`、同一明文块在不同位置密文不同、
  没有随机 IV。我们穷举过 DES/3DES/Blowfish/CAST/RC2/AES/IDEA/SEED ×
  ECB/CBC/CFB/OFB/CTR × 多种密钥派生，**全部不匹配**。
  ⇒ 结论：别试图用纯 Python 复刻，直接调 DLL（`probes/crack_bf.py`、
  `probes/probe_cipher.py` 是当时的穷举脚本，留着做记录）。

### 3.1 为什么要一个 32 位宿主

`TP.dll` / `Socket.dll` 是 **32 位**库，64 位 Python 加载不了。方案：

```
Python(64) → subprocess → XJCodec32.exe(32位, .NET) → LoadLibrary(TP.dll) → DS1/DS2
```

`XJCodec32.cs` 用 `LoadLibraryEx(path, 0, LOAD_WITH_ALTERED_SEARCH_PATH)` 全路径加载，
用 stdcall 调用导出函数；Python 端 `subprocess(..., creationflags=CREATE_NO_WINDOW)`
（`0x08000000`）保证不闪黑框。宿主只有 7 KB，随程序分发。

> 早期版本（0.1/0.2）用 `SysWOW64` 的 PowerShell + `Add-Type` 中转，
> 每次都要启动 PowerShell，慢且会弹黑框，0.3 起换成自带宿主。

## 4. 明文结构

明文 = **19 个 Ruby Marshal 对象首尾相接**，每个都以 `04 08`（Marshal 4.8）开头：

| # | 变量 | 内容 |
|---|---|---|
| 0 | `characters` | 队伍角色的行走图 `[名字, 色相]` |
| 1 | `frame_count` | 游戏帧数（60 帧 = 1 秒） |
| 2 | `$game_system` | 音量、保存次数、改名开关等 |
| 3 | `$game_switches` | `@data` 布尔数组 |
| 4 | `$game_variables` | `@data` 数值数组 |
| 5 | `$game_self_switches` | 独立开关 Hash |
| 6 | `$game_screen` | 画面震动/闪烁/天气 |
| 7 | `$game_actors` | `@data` 全部角色 + 召唤兽（下标 = `@actor_id`） |
| 8 | `$game_party` | `@actors` 出战队伍、`@原id`/`@现id`、步数、金钱袋 |
| 9 | `$game_troop` | 当前战斗队伍 |
| 10 | `$game_map` | 地图状态（含 `RPG::Table` 通行表） |
| 11 | `$game_player` | 玩家坐标与朝向 |
| 12 | `$data_items` | 数据库快照：物品（**含运行时新增的物品实例**） |
| 13 | `$data_classes` | 数据库快照：职业 |
| 14 | `$data_weapons` | 数据库快照：武器 |
| 15 | `$data_armors` | 数据库快照：防具 |
| 16 | `$data_actors` | 数据库快照：角色（21..998 同时被当成"召唤兽槽位"用） |
| 17 | `$data` | `System::Data`：`@pack`/`@wallet`/`@talisman`、`@cash`、`@fame` |
| 18 | `$存档id` | 机器码数组 |

**关键**：游戏是**逐个** `Marshal.dump` 的，所以

* 每个顶层对象有**独立的链接表**（解析时要按对象重置）；
* **跨对象不能用 `@N` 链接**；
* 同一个角色在 `#7` 和 `#8` 里各存一份**独立的副本**，改的时候两份都要改。

## 5. Ruby Marshal 4.8 细节

### 5.1 整数编码（非标准变体）

| 首字节 | 含义 |
|---|---|
| `0x00` | `0` |
| `0x01..0x04` | 正数多字节：后跟该字节数个字节，**小端无符号** |
| `0x05..0x7F` | 直接值 = `c - 5`（覆盖 0..122） |
| `0xFC..0xFF` | 负数多字节：后跟 `256 - c` 个字节，小端**二补数** |

> 坑：正数多字节**不要**做符号扩展（字符串长度 128 存为 `01 80`）。
> 字符串长度、符号名长度、数组/Hash 长度、ivar 计数都用这套 `w_long`。

### 5.2 对象链接 `@N`（**最容易写坏存档的地方**）

Ruby 存盘时，**同一个对象**在流里第二次出现不再重写，只写一个 `@编号`。

* 编号 = **对象在流里出现的顺序**，从 0 递增；
* **除 `nil` / `true` / `false` / Fixnum / Symbol 之外，一切对象都占编号**
  （包括 `String` / `Array` / `Hash` / `Object` / `Struct` / `Float` / `Bignum` /
  `UserDef`（`RPG::Table`））；
* `@N` **只能引用前面出现过**的对象。

实测本作原档 `$data` 流（4975 字节 / 138 个对象）里就有这种情况：

```
格1（佛手）对象编号 35~44：35:Array[2] 36:RPG::Item 37:Str('佛手') 38:Str('佛手') ...
格2（佛手）对象编号 45~46：45:Array[2] 46:RPG::Item      ← 只有 2 个对象！
          它的 @name/@icon_name/@menu_se 全是 '@37' / '@38' / '@41' 这样的链接，
          指向格1 内部的对象
```

⇒ 如果你只替换格1 的字节、而新块内部的对象个数/顺序变了，
**格2 之后的所有 `@N` 都会指错对象**，游戏读到的名字变成数组 →
`TypeError: cannot convert Array into String`，物品也就"无法使用"了。
**而这种错误在字节层完全看不出来**，必须比较"链接展开后的字段值"才能发现。

本工具的应对：

| 场景 | 做法 |
|---|---|
| 改标量（金钱、等级、数量…） | 只重编码那个字段的字节区间 |
| 改一个数组元素（物品格） | `PatchEngine.set_array_element`：整格替换 + 同步内存树 + 登记为"根" |
| 整体重写一个对象（加/删 ivar、数组长度变化） | `PatchEngine.replace_object`：整块重写并登记为"根" |
| 动过物品栏 / 角色对象 | 保存时**整条重写**对应的顶层对象（`replace_tree` + 自包含序列化，链接全部展开） |
| 写回前 | `Doc._check_links()` 全树体检，有 `target is None` 就**拒绝写入** |

`M.serialize()` 是"自包含序列化"：遇到 `LinkNode` 就把目标对象**内联展开**成独立副本，
输出里不含任何 `@N`，所以编号永远自洽（体积会略增，对游戏无影响）。

### 5.3 符号表

符号 `:` 与符号链接 `;`+索引 使用**独立的符号表**（不是对象表），
索引同样带 +5 偏移。

### 5.4 bignum / float / userdef

* `l`（bignum）：符号字节（`'+'` / `'-'`）+ `w_long(16 位字数)` + 小端字（顺序容易写错）；
* `f`（float）：`f` + `w_long(长度)` + ASCII 文本（如 `"0.0"`）；
* `u`（userdef，`RPG::Table`）：`u` + 类名 + `w_long(字节数)` + 原始字节 ——
  工具把它当**不透明数据**原样保留，不解码也不修改。

## 6. 两处"防作弊"

### 6.1 LockNumber（金钱等数字）

脚本 `0007` 定义。`$data.@cash`（金钱）等字段不是整数，而是一个 `LockNumber` 对象：

```
@key1[6]   1..9
@key2[6]   100..999
@value[6]
@key3[6]
```

读取时 6 组必须**一致**，否则游戏进入死循环（不是崩溃，是卡住）。
修改时要用构造公式重算：

```
value = v - v/2
key3  = v/2
```

本工具的 `Doc.set_gold()` 会一起重算 6 组，所以不会触发惩罚。

### 6.2 `$存档id`（机器码）

`$存档id` 是一个字符串数组，读档时与当前机器的机器码（`Socket.dll` 的 `GetID`）比对，
不含本机机器码就会提示**"存档的主人不是你"**然后退出。

* 本机机器码示例：`178BFBFF00A40F41`（16 位十六进制串）；
* 换电脑玩要改这里：工具「机器码」页点【填入本机机器码】再保存。

## 7. 等级 ↔ 经验

脚本 `0044 Game_Actor` 的 `make_exp_list`：

| 角色类型 | 每级增量 | 等级上限 |
|---|---|---|
| 人物（`@actor_id ≤ 20`） | `i*i*100 + i**3` | 175 |
| 召唤兽（`@actor_id > 20`） | `i*i*50 + i**2` | 180 |

`level=` 会把 `@exp` 设成 `@exp_list[level]`，所以工具改等级时**自动同步经验**
（`exp_for_level()`），不会出现"等级对了但经验还是旧值"的怪状态。

## 8. 校验与自检

工具每次保存都会：

1. 用 `M.parse_stream()` 重新解析新明文（解析不了就中止 —— 保证不写出坏档）；
2. 备份原文件为 `sy.ogg.bak`；
3. `DS1` 加密写回；
4. **重新 `DS2` 解密读回**，与预期明文逐字节比对，不一致就报错。

另外 `tests/` 里的回归测试会逐字段比较"链接展开后的值"，
而不是只比字节 —— 这正是当年 0.4 版本"测试全绿但存档已坏"的教训。
