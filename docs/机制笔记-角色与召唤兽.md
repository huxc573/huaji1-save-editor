# 机制笔记：角色与召唤兽

相关脚本：`0044 Game_Actor`、`0048 Game_Party`、`0143 Sys::Window_Baby`、
`0163`（召唤兽属性窗口）、`0164`（召唤兽图鉴）、`0011`（`$pet` 名字表）、
`0040 Game_Battler`、`0121`（战斗）。

---

## 1. 人物 vs 召唤兽

游戏用 **`@actor_id`** 区分：

| `@actor_id` | 类型 |
|---|---|
| `1 ~ 20` | 人物 |
| `21 ~ 998` | 召唤兽（"槽号"） |

数据存在**两个顶层对象**里（同一个角色的两份独立副本）：

| 位置 | 内容 |
|---|---|
| `#7 $game_actors.@data` | 全部角色/召唤兽（下标 = `@actor_id`） |
| `#8 $game_party.@actors` | 出战队伍里的那一个（游戏界面读的是这份） |

> `#16 $data_actors` 是**模板表**（`Data/Actors.rxdata` 的运行时快照），不是进度。
> 但它的 `21..998` 段同时被当作"召唤兽槽位"用，见第 3 节。

工具里改字段时**两份副本一起改**（`Doc.actor_nodes()`）。

### 1.1 关键字段

通用（`Game_Battler` / `Game_Actor`）：

```
@name @class_id @level @exp @hp @sp @latent（潜力）@vitality（活力）@spirit（体力）
@tizhi @moli @liliang @naili @minjie（五维）@五行
@weapon_id @armor1_id … @armor5_id
@add_tizhi @add_moli @add_liliang @add_naili @add_minjie
@maxhp_plus @maxsp_plus @str_plus @dex_plus @agi_plus @int_plus
@skills（技能 id 数组）@states（状态 id 数组）
```

召唤兽专有：

```
@成长 @loyal（忠诚）
@攻击资质 @防御资质 @体力资质 @法力资质 @速度资质 @躲闪资质
@修炼等级（5 项） @weapon（RPG::Weapon 对象）
```

**坑**：`@成长` 之类字段常常是 `'@N'` **对象链接**（多只召唤兽共享同一个 `0.0`），
直接改值会失败 —— 工具会把链接"物化"成独立标量，并置 `_actors_dirty`
让顶层对象整条重写（因为物化会多占一个对象编号）。

## 2. ★ 召唤兽的界面顺序 = 主人 `@babys` 的顺序

```ruby
# 0143 Sys::Window_Baby#refresh —— 召唤兽界面就是按这个顺序画的
for i in @actor.babys
  @data.push($game_actors[i])
end
```

* `@babys` 存的是**槽号**（21..998），**不是模板 id**；
* 顺序 = **获得顺序**，也就是界面顺序（**不是按 `@actor_id` 排序**）；
* 槽号 → 原始模板 id 的映射表在 `$game_party` 里：

  ```
  $game_party.@现id[k]  = 槽号
  $game_party.@原id[k]  = 原始模板 id
  $game_party.@编号     = 已分配的槽位数
  ```

实测某存档：

| 项 | 值 |
|---|---|
| 人物 12 的 `@babys` | `[165, 166, 167, 169, 168]` |
| 对应（显示名 / 模板） | 白麒麟/145、二郎真君/150、哮天犬/146、周杰伦/127、二郎真君/150 |
| `@现id[:11]` | `165,166,167,169,170,171,172,173,174,175,176` |
| `@现id[23]` | `168`（模板 150） |

对应实现：`Doc.pet_owner_map()`、`Doc.pet_slot_map()`、`Doc.pet_display_order()`。

### 2.1 ★ 槽位数组里可能是 `'@N'` 链接（v1.2 修的 bug）

`$game_actors.@data[槽位]` **不一定是对象**，也可能只是个 `'@N'` 引用：

```ruby
$game_actors.@data[165]  ==  '@62'      # 数组里是引用
# 真正的 Game_Actor(@actor_id=165, @new_name="二郎神【攻】")
#   嵌在  $game_actors.@data[12].@who_attack_me.@who_attack_me
```

* Ruby 里 `$game_actors[165]` 照样能取到对象，**游戏显示完全正常**；
* 但工具若只认 `ObjNode`，那只召唤兽就在列表里"消失"
  （用户实测：游戏里 3 只，工具只列 2 只）；
* ⇒ 按数组下标找对象的地方**必须解引用**（`Doc.actors()` 已统一处理）。
  这类"宠物被挂进人物战斗状态对象"的写法只在**打过架的存档**里出现，
  所以老版本在有战斗残留的档上才犯病。

## 3. ★ "放生"不会删掉 `Game_Actor` 对象

```ruby
# 0044 Game_Actor#remove_baby
def remove_baby(baby_id)
  $game_party.删除(baby_id)      # 0048：@原id[槽] = 999；$data_actors[槽] = 空白模板
  @babys.delete(baby_id)         # 只从主人的 @babys 里删掉
  $data_actors[baby_id] = nil
  $game_party.remove_actor(baby_id)
  @baby = 0 if @baby == baby_id
end
```

⇒ **`$game_actors[baby_id]` 这个对象仍然留在存档里**。

实测：`@actor_id > 20` 的 `Game_Actor` 有 **16** 个，但只有 **5** 个被 `@babys` 引用
（其余 11 个是"已放生 / 残留"）。

所以工具**默认只列有主的**；勾上「显示无主（已放生）的召唤兽」才能看到残留数据
（这些行显示为灰色）。

## 4. ★★ `$pet` 名字表 —— 改错名字会让游戏崩溃

### 4.1 表长什么样

脚本 `0011`：

```ruby
$pet = {   #攻击资质,防御资质,体力资质,法力资质.速度资质,闪躲资质.成长，参战等级
  "大海龟"  => [960,960,3600,1200,840,1320,[0.882,...],0],
  "二郎真君" => [2000,2000,6000,4000,1800,1800,[1.4,...],0],
  ...
}
```

* 键 = **宠物名字**（本作 154 个）；
* 值 = `[攻击资质, 防御资质, 体力资质, 法力资质, 速度资质, 躲闪资质, [成长…], 参战等级]`。

### 4.2 崩溃点（没有 nil 判断）

| 脚本 | 行 | 代码 |
|---|---|---|
| `0163 Sys <召唤兽>` | **147** | `$pet["#{baby.name}"][7]` ← 打开召唤兽界面就崩 |
| `0163` | 436 / 439 | `$pet[@baby_window.baby.name][7]`（参战按钮） |
| `0121` 战斗 | 572 | `$pet[@baby_window.baby.name][7]` |
| `0164` 图鉴 | 231 / 242 | `zz = $pet[baby.name]` |

而 `Game_Actor#name` 就是 **`@name`**：

```ruby
# 0044 Game_Actor#setup（读档时走）
@name = actor.name.split(/【/)[0]
baby  = $pet["#{@name}"]      # 这里反而有 nil 判断，所以加载时不会崩
if baby != nil
  ...按 $pet 初始化 攻击资质/防御资质/...
```

⇒ **召唤兽的 `@name` 必须是 `$pet` 里的某个键**，否则：

```
脚本 'Sys <召唤兽>' 的 147 行发生了 NoMethodError.
undefined method '[]' for nil:NilClass
```

### 4.3 改名的正确姿势

游戏里的"改名"功能（`0163 when 16`，消耗 30 点活力）写的是 **`@new_name`**：

```ruby
# 0040 Game_Battler
attr_accessor :new_name
def custom_name
  @new_name.nil? ? name : @new_name      # 显示名
end
```

* `@new_name` **不参与 `$pet` 查表** → 随便改都不会崩；
* `@name` 参与查表 → 只能是 `$pet` 里的名字。

| 工具里的按钮 | 写哪个字段 | 安全性 |
|---|---|---|
| 【设为显示名(@new_name)】 | `@new_name` | ✅ 随便改 |
| 【改基础名(@name)】 | `@name` | ⚠️ 必须是 `$pet` 表里的名字（工具会先拦截） |
| 【清除显示名(恢复原名)】 | 删掉 `@new_name` | ✅ |
| 【恢复模板本名】 | `@name` ← `$data_actors[模板].name.split('【')[0]` | ✅ 复刻游戏算法 |
| 【一键修复名字】 | 批量上面那一条 | ✅ |

> `@new_name` 平时**根本不在存档里**（`Game_Battler#initialize` 不设置它），
> 所以改名等于"给对象追加一个 ivar" → 对象字节变长 → 流里对象个数变化 →
> 后面所有 `@N` 编号错位 ⇒ 必须整条重写 `$game_actors` / `$game_party`。
> 清除时也要**真的删掉**那个 ivar（把值设成空字符串不行，游戏会显示空白）。

### 4.4 名字表从哪来

| 优先级 | 来源 |
|---|---|
| 1 | 现场解析 `<游戏目录>\Try\scripts\0011_*.rb`（从存档目录/当前目录/程序目录逐级向上找） |
| 2 | 随程序携带的 `src/pet_table.py`（由 `tools/gen_pet_table.py` 从同一脚本生成） |

两张表都拿不到时 `Doc.pet_name_ok()` 返回 `None`，界面就不显示警告（不会误报）。

## 5. 技能（`@skills`）

* 人物、召唤兽都用 `@skills`（技能 id 数组）；
* 脚本 `0044`：

  ```ruby
  learn_skill(skill_id)  → @skills.push(skill_id); @skills.sort!   # 保持升序
  forget_skill(skill_id) → @skills.delete(skill_id)
  skill_learn?(skill_id) → @skills.include?(skill_id)
  ```

* 技能**模板不在存档里**，在 `Data/Skills.rxdata`（本作 **233** 个技能，
  如 嗜血追击 / 地狱烈焰 / 高级必杀 / 龙卷雨击 / 五雷咒…）；
* 数组长度会变 ⇒ 改完技能要整条重写 `$game_actors` / `$game_party`；
* 工具里：【学会技能】（自动升序、重复会提示）/【忘掉选中】/【清空技能】/【克隆技能…】，
  带技能搜索框（打 `高级` 或技能 id 都能筛）；
* **技能描述**取自模板对象的 `@description`（`Doc.skill_desc(sid)`），
  表格里直接显示，搜索也会匹配它；
* **克隆技能**（v1.3）：`Doc.clone_skills(src, dst)` = 把 `src` 的整张技能表
  写进 `dst`（复用 `set_actor_skills`，会置 `_actors_dirty`）。
  目标即使是个 `'@N'` 链接对象也能克隆；`set_actor_skills` 一律换**新数组**，
  所以源绝不会被连带改掉。

## 6. 参战 / 携带等级

* 携带等级 = `$pet[名字][7]`：**角色等级必须大于它**才能带这只宠；
* 参战还要求：召唤兽等级不能比人物高 10 级以上（`0121`）；
* 参战状态的字段是 `@baby`（主人身上的"当前参战召唤兽槽号"，0 = 没参战）。

工具里召唤兽表直接显示了这两项相关的列（「携带等级」），方便对照。
